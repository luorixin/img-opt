# 图像清理工具 (Image Cleaner) 更新文档 - 2026-06-25

本更新文档详细记录了 2026-06-25 在系统性能、模型热加载、多图像格式导出以及前端 UI/UX 操作便捷性等方面所做的重大升级与优化。

---

## 🚀 新增功能 (New Features)

### 1. 全链路多格式图像导出 (Multi-Format Support)
*   **后端格式编码适配**：
    *   超分 (`run_upscale`) 和背景分割 (`remove_background`) 接口与底层的 Celery 异步任务、同步线程池处理全面支持 `PNG`、`WEBP`、`JPEG` 格式导出。
    *   针对 `JPEG` 格式不支持透明度的问题，在超分后端实现中增加了智能 Alpha 通道合并：若输入为带有透明度的 `RGBA` 图像，则自动将其融于纯白色底图（`RGB(255, 255, 255)`）之上再进行保存，避免 Pillow 报错崩溃。
    *   优化了 `WEBP` 与 `JPEG` 的压缩质量因子（分别为 `85` 和 `85`/`90`），大幅缩减导出的网络传输体积。
*   **前端格式选择切换与持久化**：
    *   在前端工具栏中增加了“💾 导出格式”选择器，允许用户在 `WEBP`、`PNG`、`JPEG` 之间进行单选切换。
    *   选中的格式状态已被集成到 Zustand 状态管理 (`useStore.ts`) 中，并自动持久化写入 IndexedDB 本地数据库 (`db.ts`)，以便在页面刷新后仍可保持历史偏好设置。
    *   在执行大图去背景、清晰超分、局部抠图下载或批量 AI 导出时，前端会自动传递当前的导出格式参数，并自适应将下载保存的文件扩展名修改为对应的 `.webp` / `.png` / `.jpg`。

### 2. 撤销/重做历史深度可视化与快捷键提示面板
*   **历史操作深度指示**：
    *   在工具栏撤销和重做图标旁，直观地显示当前蒙版绘制历史栈的深度数字（例如 `撤销 (3)`，`重做 (1)`），让专业用户能够清晰掌握当前操作进度。
*   **手绘风格快捷键提示弹窗**：
    *   工具栏最下方新增了 `⌨️ 快捷键说明` 触发器，点击后弹出一个优雅的手绘风格弹窗，为用户提供完整的键盘快捷键一览（包括撤销、重做、笔刷缩放、各种工具切换、空格拖拽画布平移等），提升生产力。

## ⚡ 性能优化 (Performance Optimizations)

### 1. 后端 AI 推理多硬件动态加速 (CUDA & CPU Execution Provider)
*   **动态加速检测**：修改 `ai_engines.py` 中的 ONNX Runtime 初始化，动态检测系统可用的 execution providers。
*   **自定义加速通道**：引入 `UPSCALER_PROVIDER` 环境变量，允许部署人员在容器启动时通过环境变量显式覆盖或指定加速卡（如 `CUDAExecutionProvider` 优先）。
*   若未配置环境变量，则默认按照 `CUDAExecutionProvider` -> `CPUExecutionProvider` 的优先级顺序自动加载。

### 2. 可选 AI 模型热加载预热 (Lifespan & Subprocess Warm-up)
*   **默认懒加载降低空闲内存**：
    *   FastAPI Web 容器和 Celery Worker 默认不再启动时预载 Real-ESRGAN 模型，避免 API 进程与 Worker 重复常驻同一份推理内存，也减少 Docker 启动阶段的 CPU 峰值。
    *   如本地或专用服务器更关注首个任务延迟，可通过 `BACKEND_AI_PRELOAD_MODELS=true` 或 `WORKER_AI_PRELOAD_MODELS=true` 分别控制 API 与 Worker 预热；旧变量 `AI_PRELOAD_MODELS` 仍作为兼容 fallback。
*   **Celery 多进程 Fork 安全加载**：
    *   保留 Celery `worker_process_init` 信号作为可选预热入口；开启预热时仍在子进程内独立加载 ONNX Runtime，避免父进程初始化后 fork 继承线程池导致死锁。
*   **健康检查接口增强**：
    *   健康检查端点 `/health` 中增加了 `"upscaler": {"loaded": True/False}` 字段，使上游探针或反向代理能精确检测 AI 模型预载状态。

### 3. Docker 资源占用收敛
*   **Compose 资源上限**：
    *   为 Redis、Backend、Worker、Frontend、IOPaint 与 diffusion 侧车增加 `cpus` 与 `mem_limit` 默认值，所有限制均可通过 `.env` 中的 `*_CPUS` 和 `*_MEMORY_LIMIT` 覆盖。
    *   默认重点限制空闲常驻服务，避免 Docker Desktop 把单个容器显示成拥有整台 Docker VM 的内存上限。
*   **ONNX Runtime 线程限制**：
    *   新增 `UPSCALER_INTRA_OP_THREADS` 与 `UPSCALER_INTER_OP_THREADS`，默认均为 `1`，降低 CPU 超分任务对宿主机的抢占；大图批处理场景可按机器核心数逐步调高。

### 4. 导出格式一致性修复
*   **异步任务媒体类型透传**：
    *   Celery 任务结果现在会把 `content_type` 与结果文件一起透传给 `/api/tasks/{task_id}/result`，WEBP/JPEG 异步导出不再被固定标记为 `image/png`。
*   **端侧 Canvas 真实编码**：
    *   快速模式透明背景、清晰增强和切图导出会按所选 `PNG`、`WEBP`、`JPEG` 调用 Canvas `toBlob`，避免只修改文件扩展名但实际内容仍是 PNG。
