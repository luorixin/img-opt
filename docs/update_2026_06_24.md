# 图像清理工具 (Image Cleaner) 更新文档

## 2026-06-24 更新

### 🐛 修复问题 (Bug Fixes)
1. **修复智能选区 (Smart Segment) 无响应问题**
   - **问题现象**：在前端工具栏选择“智能选区”工具并在图片上点击时，只会画出一个红色的细小点，并未向后端发起真实的 SAM (Segment Anything) 分割请求，导致“没效果”。
   - **根本原因**：`useCanvasDrawing.ts` 的 `beginStroke` 鼠标落下事件和 `continueStroke` 鼠标移动事件中，漏掉了对 `currentTool === "smart"` 类型的拦截，导致点击操作被回退为普通的默认画笔行为 (Paint)。
   - **修复方案**：拦截 `smart` 工具并执行 `setSmartSegmentPoint` 和自增 `smartSegmentRequestId` 状态，以触发 `App.tsx` 中的 `useEffect`，进而正常向后端 `/api/segment` 接口发送请求。

2. **修复后端 Inpaint API 崩溃问题 (500 Error)**
   - **问题现象**：`UnicodeDecodeError - utf-8 codec can't decode byte 0x89`。
   - **修复方案**：已将 `IOPaintSidecarEngine.inpaint` 方法在请求 Python 端 sidecar 时，由旧的 `Multipart/Form-Data` 数据格式切换为 Base64 JSON 格式发送。

### 🚀 性能优化 (Performance Optimizations)
1. **批量处理并发控制 (Batch Concurrency)**
   - **现状改善**：批量处理由原本完全串行的 `for` 循环等待改写为基于 `AsyncQueue` 的并发控制模式。
   - **实现细节**：新增自定义队列类，支持设置最大并发度 (如同时处理 3 张图片)，显著提升大规模图片批量消除时的整体效率。

2. **Service Worker 缓存策略升级 (PWA 离线化增强)**
   - **现状改善**：原本采用的是手动编写的 `sw.js` (网络优先/部分缓存优先)，只能缓存主页面，不能对 Vite 编译出来的带 hash 的内部模块和静态资源（如图标）进行预缓存，导致“秒开”和完全离线体验存在瑕疵。
   - **实现细节**：引入并配置了 `vite-plugin-pwa`。构建阶段自动分析依赖生成带有 Workbox 预缓存列表的 `sw.js`。现在所有 HTML、CSS、JS Chunk 甚至图片图标字体，都会在首屏加载完后在后台完成 `install`，从而在日后达到断网下的 **秒开（完全离线工作）** 体验。

## 2026-06-24 图像算法升级与后端 AI 任务整合

### 🚀 新增功能 (New Features)
1. **端侧与后端 AI 双算法模式选择**
   - 在前端 Toolbar 侧边栏新增了“算法模式”选择按钮组（快速模式 vs AI 模式），支持将设置持久化同步至 IndexedDB 浏览器本地存储。

2. **快速模式 (端侧算法保留)**
   - 完整保留并包装了原先纯浏览器的 Canvas 像素和滤镜算法（透明背景颜色容差、清晰插值与局部锐化切图等），作为“快速模式”提供毫秒级的即时响应。

3. **AI 模式 (后端 AI 超分/背景分割任务)**
   - **AI 背景分割**：在后端新增 `/api/remove-background` 接口和 Celery 异步任务 `remove_background_task`。基于高效的 `rembg` (U2-Net) 模型自动识别人像和前景，实现一键生成高精度透明背景 PNG。
   - **AI 超分辨率重建**：在后端新增 `/api/upscale` 接口和 Celery 异步任务 `upscale_task`。集成 `onnxruntime` 推理引擎，在 CPU 级硬件上高效执行 pre-trained Real-ESRGAN 超分模型。
   - **倍率与裁剪整合**：超分接口不仅支持 AI 模式下 2x、3x、4x 的整图超分，还支持传入裁剪框坐标字符串（`x,y,w,h`），直接在后端完成抠图并基于 AI 模型做超分重建。

4. **批量处理 AI 升级**
   - 批量透明背景与批量清晰增强功能均适配了当前的算法模式。在 AI 模式下，批量图片的处理也将完全通过后端接口并发运行，产出更高精度的高保真图像。

### 🔧 技术改进 (Technical Enhancements)
1. **轻量化 AI 依赖与无需 PyTorch 模型推理**
   - 我们没有引入动辄 1.5GB+ 尺寸的 PyTorch 框架，而是使用高效、跨平台的 `onnxruntime` 进行模型推理，并自动将 Real-ESRGAN 2x ONNX 模型文件下载缓存于本地 `~/.cache/img-cleaner/`。对于 4x/3x 倍率，我们通过连续 2x 推理与高精度 `LANCZOS` 下采样结合的算法来实现，从而将容器运行底噪和镜像打包耗时降到最低。

2. **异步队列与 Celery Worker 完美契合**
   - AI 背景消除和超分任务在开启 `TASK_QUEUE_ENABLED` 时，自动使用 Celery 推入 Redis 队列进行异步计算，并在前端以进度百分比和加载状态进行平滑轮询（Polling）。在队列禁用时，将平滑回退为后端同步处理，兼顾了灵活性与性能瓶颈下的吞吐稳定性。

## 2026-06-24 未提交改动审查修复

### 修复问题
1. Redis 限流键改用 SHA-256 指纹，不再把原始 API Token 写入 Redis。
2. AI 接口增加解码像素、裁剪边界和输出像素限制，越界或超额请求在入队前返回 400/413。
3. 队列关闭时，去背景和超分通过线程池运行，避免阻塞 FastAPI 事件循环。
4. Celery 任务 ID 与输入目录统一，并增加活动租约和取消标记；未知任务不再返回虚假的取消成功。
5. 多区域切图与批量 AI 处理改为跟踪全部任务 ID，取消操作覆盖所有活动任务，失败时等待已启动任务收尾。
6. IndexedDB 防抖保存改为串行队列，支持页面隐藏时立即落盘，并在清缓存前取消待写快照。

### 性能与可靠性优化
1. Real-ESRGAN 下载增加跨进程文件锁、超时、SHA-256 校验、唯一临时文件和原子替换。
2. Compose 新增 `ai-models` 持久卷，后端与 Worker 共享 Real-ESRGAN 和 rembg 模型缓存。
3. 任务输入、活动租约和结果使用独立过期时间，降低排队任务被普通结果 TTL 误删的风险。
4. Python 图像推理依赖固定为已验证版本，减少不同时间构建产生不一致行为。

### 配置项
- `MAX_IMAGE_PIXELS`：允许解码的最大输入像素数，默认 `25000000`。
- `MAX_OUTPUT_PIXELS`：允许生成的最大输出像素数，默认 `67108864`。
- `TASK_INPUT_EXPIRES_SECONDS`：排队输入保留时间，默认 `86400`。
- `TASK_ACTIVE_EXPIRES_SECONDS`：异常活动租约最大保留时间，默认 `86400`。
- `UPSCALER_MODEL_PATH`：Real-ESRGAN 模型文件路径。
- `UPSCALER_MODEL_SHA256`：模型完整性摘要。
