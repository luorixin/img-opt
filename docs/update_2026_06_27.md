# 图像清理工具 (Image Cleaner) 更新文档 - 2026-06-27

本更新文档详细记录了 2026-06-27 对前端性能开销、网络上传瓶颈以及预览区交互机制所做出的三项重磅升级优化。

## 🚀 新增功能 (New Features)

### 1. 结果对比滑动条 (Before/After Split Slider UI)
*   **像素级分屏对比**：
    *   将结果预览面板 (`ResultPane.tsx`) 升级为交互式对比滑动条。如果原图和 AI 处理后的结果图同时存在，则渲染重叠视口并启用垂直滑动线与双向拖拽手柄。
    *   在顶层结果图上采用 CSS `clip-path: inset(0 0 0 X%)` 属性进行动态裁剪，无缝暴露出底层的原始图像，支持用户通过左右拖动随时比对细微的噪点消除、超分辨率重建或透明边缘切割的效果细节。
*   **HTML5 指针捕捉与边界控制**：
    *   利用 `setPointerCapture` 与 `releasePointerCapture` 对鼠标和触控指针进行锁定。即使用户在拖动过程中将光标移出浏览器窗口或预览区之外，滑动操作依然平滑可控。
*   **等比例视口锁定与手绘风格标签**：
    *   在 `App.tsx` 中将当前图像的 `width` 和 `height` 等比例传入，自动通过 `aspect-ratio` 限制滑动视口，保证原图与结果图完美对齐且不发生比例形变。
    *   增设了左右“原图”（墨绿色）与“效果图”（橙红色）的手绘边框小标签，保持系统的“粗线描边”手绘插画风格。

## ⚡ 性能优化 (Performance Optimizations)

### 1. IndexedDB 存储分离与高频保存零卡顿
*   **现状改善**：
    *   原先自动保存机制在每次用户绘制蒙版停笔时，都会将包含巨大原图 File 对象的整个 App 状态对象全量写入 IndexedDB 数据库，高频的磁盘 I/O 极其容易导致 UI 掉帧卡顿，且极易触发浏览器配额超限报错 (`QuotaExceededError`)。
*   **分离存储设计**：
    *   在 `AppStateStore` 对象库中新增 `"latestImageFile"` 键以独立存储原图 File 对象，而元数据则存放在 `"latestState"` 键中。
    *   在保存时增加基于 File 指纹（名称、大小、最后修改时间、引用）的缓存比对机制。仅当用户导入新图片或清空工作区时，才对 `"latestImageFile"` 进行写操作；其余高频的涂画动作，仅写入体积微小的 metadata。
    *   在加载时并发读取两部分内容并重组返回。同时保持对旧版全量存储模式的无缝向下兼容，保障老用户无痛升级。

### 2. 蒙版游程编码 (RLE) 压缩
*   **高压缩比算法**：
    *   在 `db.ts` 中针对蒙版像素数据高稀疏性的特征（由海量重复的 0 和少量的 255 构成），实现了纯手写的 `compressMaskRLE` 与 `decompressMaskRLE` 游程长度压缩算法。
    *   该算法能将数 MB 体积的 `Uint8ClampedArray` 蒙版压缩至几字节（若无涂抹）到几 KB。大幅降低了高频自动保存时的 CPU 与磁盘负载。
*   **向下兼容**：
    *   反序列化加载时如果检测到旧的未压缩 `alpha` 蒙版，则直接读取；若是新版 `rle` 数据则自动解压还原，确保升级时用户工作进度无损。

### 3. 客户端级大图预压缩与转码
*   **带宽防爆与提速**：
    *   在前端载入图片处增加 `compressAndConvertImageFile` 辅助器，用于自动拦截体积超过 10MB 的超大/无损图像文件。
    *   利用离屏 Canvas 在前端异步转码并轻度压缩为 92% 高保真质量的 WebP（含透明度）或 JPEG 格式。压缩率高达 70%-90% 以上且肉眼完全无损。
    *   此机制大幅减少了向后端接口发送修复或超分请求时的网络数据传输带宽，使超大图片上传至接口的时间缩短了数倍，并避免了由于大文件上传超时的接口报错。
